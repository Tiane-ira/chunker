功能二：切片与向量化处理
功能描述：基于已完成去重、解析、打标和元数据抽取的主文件，将长文本按照法律语义结构进行切片，并为每个切片生成向量及索引。整体切片及向量索引生成策略可参考项目问答中合同文件&投后报告切片情况。
1.切片策略——法律语义感知切片
切片的核心原则是：确保法律条款的语义完整性，严禁切断“法条”逻辑单元，同时兼顾上下文关联。
（1）主切片策略——基于法律结构
多级降级切片策略，按优先级执行：
优先级	判断依据	切片规则	示例
P0（条款）	识别到“第X条”、“第X章”、“（一）”、“一、”等结构化序号	以单个条款/章节为最小单元进行切分，切除的块需包含该条款的完整编号和全部正文内容。	“第四条 合格投资者是指……风险承担能力。” 必须完整切为一个块，不允许拆成上下两段。
P1（段落）	无明确条款序号，但存在自然换行（\n\n）	以双换行符为分隔符，将连续语义段落切为一组。	针对“通知”或“决议”类文件，按段落切分。
P2（长度兜底）	无结构标题，且段落超长（> 800 tokens）（具体长度以开发老师设计为准）	采用递归字符切片，以句号、分号、问号等标点为次级分隔符，确保单个切片不超过上限（比如默认 800 tokens）。	纯文本流式文件。
特殊规则（禁止切断）	包含“《》”文件名或 URL 链接	强制该部分整体保留在当前切片中，不允许将其切断到下一个切片。	防止法规名称“《证券投资基……”被截断。
（2）上下文增强策略——父子块索引
为解决法规条文较短（如“见前条”）导致检索语义不足的问题，引入父子块机制（可以参考顾辉老师RAG平台策略）：
块类型	定义	检索粒度	输入给LLM的粒度
子块	按上述主切片策略中P0/P1规则生成的最小原子块，用于与用户问题进行语义比对（检索入向量库）。	检索召回时，匹配到的是子块。	返回该子块所属的父块全文（包含上下章节）。
父块	子块所在的大段落、整章或整节（窗口大小可配置，如上下各扩展1-2个段落，具体以开发老师设计为准）。	不直接参与向量匹配。	作为最终上下文输入大模型。
（3）切片重叠策略
相邻子块切片之间最好存在10%-15%的重叠长度（基于Token数），具体以开发老师设计为准。防止因标点符号误差导致关键信息恰好落在两个切片的切割边缘，造成召回时语义丢失。

2.切片输出数据规格
切片处理完成后，需生成并存储独立于原始文件的切片级记录，每条记录应包含以下字段（供后续向量化和检索使用）：
字段名称	数据类型	是否必填	说明/来源
slice_id	String	✅ 必填	全局唯一切片ID（生成规则：{file_id}_{chunk_index}）
file_id	String	✅ 必填	关联功能一中的主文件ID
parent_slice_id	String	条件必填	若当前为子块，存储其所属父块ID；若为父块，则置空
slice_text	Text	✅ 必填	切片的实际原文内容
slice_length	Int	✅ 必填	切片字符长度/Tokens数量
head_text	Text	✅ 必填	切片开头连续的 50 个字符（用于前端高亮摘要展示）
metadata	JSON	✅ 必填	透传功能一输出的关键元数据（参见下方结构）
透传的元数据（metadata）结构示例：
{  "file_name": "20150424中华人民共和国证券投资基金法.docx",  "labels": ["保险资金运用法规汇编", "综合", "一般规定", "法律"],  "publish_date": "2015-04-24",  "org": "中国证监会",  "effective_status": "生效中",  "invalid_detail": null, // 或包含失效时间、依据文件ID等  "full_path": "保险资金运用法规汇编/一、综合/（一）一般规定/..."}

3.切片向量化与索引构建
（1）向量化模型选型
选用公司内部已有的Embedding模型，可参考项目问答中使用模型；
（2）向量化输入构建
向量化的输入除了slice_text，最好将关键元数据拼接到文本前，增强检索相关性，具体以开发老师设计为准。
拼接规则：[机构名] [生效状态] [层级标签] [切片正文]
示例输入：中国证监会 部分生效 保险资金运用法规汇编 综合 一般规定 法律 20150424中华人民共和国证券投资基金法 第四条 合格投资者是指具备相应风险识别能力和风险承担能力...
（3）双引擎索引
切片处理后，并行写入以下两种索引（具体方案以开发老师设计为准），以支持AgenticRAG的关键词+语义的混合检索：
索引类型	存储引擎	索引内容	用途
向量索引（语义引擎）	Elasticsearch 向量插件 / Milvus	将上述拼接文本转为向量，建立索引	支持语义模糊检索（如“如何界定合格投资人”）
全文倒排索引（关键词引擎）	Elasticsearch (IK分词)	索引 slice_text、file_name、labels、publish_date、org  等	支持关键词精确匹配（如“《证券法》第4条”）

4. 增量更新与版本管理（排期版本待定）
若后续有新增文件，新增文件需要先与存量文件进行比对，判断新增文件类型是完全新增/内容修订/状态层级等标签变更，再分别执行不同预处理判断&切片向量化处理流程，并合并更新预处理结果表&切片向量化结果表。
场景	切片与向量化策略
新增文件入库	仅对新文件执行完整的“预处理-> 切片 -> 向量化生成 -> 写入双引擎”流程，不影响存量切片。
文件内容修订（重新解析）	标记该文件对应存量文件的 file_id 下的所有旧 slice_id 为 is_deleted: true（逻辑删除），全量重新生成该文件的新切片并写入新向量。旧向量保留备份直至人工审核确认无误（后续可能涉及数智应用系统中合规文件管理模块下文件更新审核流程；设置回滚机制）。
元数据变更（如状态改为已失效）	无需重新切片，需更新该文件对应存量文件的 file_id 对应的相应元数据字段、更新切片结果表中的该 file_id 下对应的所有 slice_id 对应元数据字段、重新拼接写入新向量。
